# Code audit — 2026-10-15 (v0.2.1, commit b21538a)

Scope: security, backend correctness, recognition accuracy, frontend/UX/a11y, packaging/CI/docs.
Method: full read of the code, plus running the unit tests, coverage, ruff, bandit, pip-audit, `tests/eval.py`, `bench/eval_bench.py` (synth2), and parser/rotation probe scripts.
Each item lists **where**, **what goes wrong**, **fix**, and how to check it's done. Items marked *(unverified)* were reasoned from code, not reproduced.

## Baseline (what's healthy)
- 307 unit tests pass (~75 s); line coverage 85%. `pip-audit`: no known vulnerable dependencies. No secrets in the repo or its history.
- Synthetic accuracy: `tests/eval.py` 108/108; `bench/eval_bench.py` on synth2 (full pipeline) 467/480 = 97.3%.
- Security fundamentals are solid: PBKDF2 310k iterations, hashed session tokens, Origin check + double-submit CSRF, CSP, upload bomb/format guards, CSV/XLSX formula-injection guard, `esc()` used on nearly every innerHTML sink, path handling via basename + allowlists, phone-mode pairing design, SHA-256-pinned AI helper downloads.
- **No Critical or High security findings.** The highest-impact problems are data-integrity races in the backend and ops issues in packaging.

## P0 — fix first (small, isolated, high impact)

### Data integrity
1. **`set_meta` silently undoes other writers.** `app/ui.py:70-73` reads the whole `card_meta` row and writes it back with `INSERT OR REPLACE`. Several writers don't hold `WRITE_LOCK`: the AI worker (~848, 901-972), export marking (~2426), retention (~2487), archive (~1932) and job ingest (~686). Example: the AI worker reads meta, a reviewer then saves `crm_action=create_new`, and the AI write puts back the stale row, so the reviewer's choice is lost.
   *Fix:* `INSERT … ON CONFLICT(card_id) DO NOTHING` followed by `UPDATE card_meta SET <only the passed columns> WHERE card_id=?`, in one transaction.
   *Check:* add a test that interleaves two `set_meta` calls touching different columns; both values survive.
2. **Export can mark cards exported without their latest edits.** `ui.py:~2407-2428` builds the file, then marks cards using metadata loaded *before* the build, all outside `WRITE_LOCK`. An edit made during the build isn't in the file, yet the card is marked exported and its `reexport` flag is cleared. The newer data never reaches MC Trade and nothing flags it.
   *Fix:* re-check `card_version` per card at marking time, and set `reexport` for any card that changed (or build and mark under the lock).
3. **The AI worker thread can die permanently.** `ui.py:833-852`: the `set_meta` calls in the worker loop, and the ones inside `_ai_run`'s except block, can raise (e.g. `database is locked`). That kills the thread, and AI checks stop until restart. The phone `_reaper` (`phone.py:~132`) has the same problem; if it dies, the LAN listener is never shut down.
   *Fix:* wrap each loop iteration in `try/except Exception: log; continue`.
4. **SQLite connection setup.** `store.db()`/`ui.db()` open a new connection on every call and re-run CREATE TABLE/ALTER/PRAGMA each time. There is no WAL mode, no `busy_timeout` (default 5 s lock wait) and no indexes.
   *Fix:* create a `db.py` that sets `journal_mode=WAL`, `busy_timeout=10000` and `foreign_keys=ON`, and runs schema setup once at startup. Add indexes: `card_history(card_id,id)`, `card_history(action,reviewer)`, `card_meta(batch)`, `card_meta(sha256)`, `actions(user_id,undone)`, `sessions(user_id)`, `exports(filename)`.
5. **Hard delete is unsafe.** `ui.py:~1085-1165` runs outside `WRITE_LOCK`, so a concurrent save can write the deleted person's merged values back. Also, `VACUUM` runs *before* the audit rows are written: if VACUUM fails with "locked", the delete is already committed, the client gets a 500, and there is no audit trail.
   *Fix:* take the lock, write the audit rows inside the transaction, and make VACUUM best-effort afterwards.
6. **Card ids get reused after a hard delete.** `store.py:6` declares `id INTEGER PRIMARY KEY` without AUTOINCREMENT. If the deleted card had the highest id, the next scan gets the same id. It then inherits the redacted history rows and is matched by old `exports.card_ids`.
   *Fix:* migrate to AUTOINCREMENT (requires a table rebuild).
7. **Admin saves apply partially.** `auth.py:330-337` (`save_settings`) validates while saving, so an invalid key returns 422 after earlier keys were already written. `auth.py:267-280` (`edit_user`) returns 422 inside `with db()`, and sqlite's context manager commits on return. Example: `{password, active:false}` on yourself resets your password and kills your sessions, then reports an error.
   *Fix:* validate everything first, then write.

### Packaging / ops
8. **Desktop and Docker backups go to the wrong place.** `app/backup.py:30` defaults to `<app root>/backups`, and nothing in `packaging/` sets `GAC_BACKUP_DIR`.
   - Desktop: backups sit inside the install folder (`_internal/backups`, or inside the `.app`), so a Mac drag-replace upgrade deletes them.
   - Docker: `/srv/gac` is owned by root, so every backup attempt fails, and the folder isn't in the volume anyway.

   *Fix:* default to a sibling of the data dir (e.g. `<data dir>/../backups`), have the launcher set `GAC_BACKUP_DIR`, and add a volume in `docker-compose.yml`.
9. **Desktop backups include the 3 GB AI model.** `backup.py:20` `SKIP_DIRS` doesn't list `ai-helper` or `webview`. With 7 backups kept, that is roughly 25 GB. The WebView profile, which holds the session cookie, is backed up too.
   *Fix:* add `ai-helper`, `webview` and `corrections` to `SKIP_DIRS`; skip `app.log` and `instance.json`.
10. **Unit tests write into the repo's real `data/`.** `tests/unit/conftest.py:70-71` redirects only `store.DB` and `crm_source.DATA` to a temp folder. That is why HANDOFF says to run tests "from a copy". Several tests in `test_r9.py` also fail intermittently under coverage, depending on timing and run order.
    *Fix:* set `os.environ["GAC_DATA_DIR"] = tempfile.mkdtemp()` at the top of conftest, before any `app` import (as `test_demo.py` already does).

### Security (Medium)
11. **DNS rebinding can create the first admin on a fresh install.** `auth.py:101-108` compares Origin with the attacker-controlled Host header. Setup (`auth.py:213`) and `/api/scan` (`auth.py:120,143`) trust loopback clients. A malicious page rebinding to 127.0.0.1:8765 can do setup before the user does, and after setup can still inject cards through `/api/scan`.
    *Fix:* add `TrustedHostMiddleware` (localhost, 127.0.0.1, [::1], configured LAN host) and compare Origin to that allowlist.
12. **Upload limits trust Content-Length.** `auth.py:125`, `demo.py:60`, `phone.py:201`. A chunked upload has no Content-Length, and handlers call `await image.read()` with no cap. Anyone with the published demo login can exhaust the Space's memory.
    *Fix:* `await image.read(MAX+1)` and reject if longer, plus an ASGI middleware that counts the body bytes actually received.
13. **Reviewers can bulk-read every card.** `GET /api/cards?archived=true&limit=0` (`ui.py:~1227`) returns everything to any signed-in user. That contradicts the export restrictions and PRIVACY-NOTE.md:16-17.
    *Fix:* apply the export role rules to `/api/cards`, or update the policy text if this is intended.

### Frontend
14. **A new batch steals photos still waiting to upload.** `app/static/ui/ui.js:~228`: `upload()` reads the global `B.id`/`B.label` when each file is sent, not when it was queued. Start batch "Event B" while Event A is still uploading, and the remaining Event A photos are filed under B and stop being tracked.
    *Fix:* store `row.batch`/`row.label` in `enqueue()` and send those; confirm before starting a new batch while uploads are pending.

## P1 — next

### Backend
- **Writes aren't atomic.** `_update` (`ui.py:~1345-1535`), bulk, archive and ingest each make 10-25 separate commits. An exception mid-way leaves half-applied merges. Use one `tx()` connection per request.
- **One request can seal another's undo snapshot.** `_UNSEALED` (`ui.py:104-121`) is global and `_seal()` pops every entry. Have `snapshot()` return its id and seal only that id.
- **A crash can create duplicate cards on recovery.** An inbox file is removed only after the card exists (`ui.py:~706`), so a kill in that window makes `recover()` re-create the card. Add a `job_id UNIQUE` column and insert card + meta + history in one transaction.
- **Blocking DB work runs on the event loop.** The auth middleware does a SELECT + UPDATE + commit on every request, including polling, and the async upload handlers write 25 MB files synchronously. Use `run_in_threadpool`, and touch the session at most once every few minutes.
- **Failed backups go unnoticed and skip a day.** One missing file aborts the whole backup, and after a failure the loop waits until the next nightly run (`backup.py:51-56,124-138`). Skip missing files, retry in 10 minutes, and show last-ok/last-error in Admin.
- **Migrations are ad hoc.** Replace the per-call `ALTER TABLE` statements with `PRAGMA user_version` and numbered migrations run once at startup.
- **`GAC_DB` is honoured by `backup.py:25` but not `store.py`.** Pick one.
- **Phone server start/stop has no lock** *(unverified)*. A bind failure happens inside the thread, so the user can be shown a QR code with nothing listening (`phone.py:111-128`).

### Performance at thousands of cards
- `/api/cards` and every save call `_active()`, which loads and decodes **all** cards. `approval_check` repeats this once per card, so bulk approve is O(N²) under the lock.
- `dupes()` fuzzy-matches every card against every CRM row before checking its cache. With a real ~10k-row contacts export this becomes millions of comparisons per request *(estimated)*. Build a blocking index on email, phone and name keys once per contacts file.
- `attention()` re-runs consistency, plausibility and geocoding for every card on every list request. Cache it per `card_version`.
- Frontend: "All batches" requests `limit=0` and renders every row; search re-renders on every keystroke; full re-fetch every 5 s while any AI check runs; each thumbnail is a full-resolution blob URL and `revokeObjectURL` is never called. Use the existing `limit`/`offset`/`X-Total` with "Load more", debounce search ~150 ms, make ~96 px thumbnails with `createImageBitmap`, and update rows in place.

### Recognition accuracy (biggest product lever)
Real-world accuracy is roughly 85% rules-only and 93% with the AI double-check (HANDOFF; not reproducible here because `bench/real` isn't in the repo). The main gaps:
- **Confidence scores are fixed constants, not evidence.** Emails 0.95, phones 0.9, and so on. Per-line OCR confidence and the Tesseract/PP-OCR agreement score are computed in `ocr.py:148-152` and then thrown away in `_finish` (`ocr.py:187`). Since the AI check only runs on low confidence (`ui.ai_reason`, `ui.py:~879`), **cards that are confidently wrong never get it.** Carry the OCR evidence into each field and calibrate against bench and corrections data. Biggest expected impact.
- **Flags go stale after the AI merge.** Consistency and plausibility run before the VLM merge and postfix (`pipeline.py:29-41`), and the UI's AI path (`ui.py:~937`) never re-runs them. Re-run them after the merge.
- **Rotation and low resolution:** rotating a card 90° drops it from 91/96 to 83/96 correct fields; one-third resolution drops it to 67/96. Both stay at high confidence with nothing flagged.
  - Detect overall orientation from the RapidOCR boxes and rotate the image upright before layout.
  - Use the cropped card as the *primary* pass when `crop_card` finds a 1.4-2.0 aspect ratio; today it only fills empty fields.
  - Ask for a retake when the card is under ~600 px wide.
- **AI double-check:** turn `VLM_CROP` on by default (`vlm.py:82`); today the whole photo is shrunk to 896 px, so card text is tiny.
- **Parser bugs, all confirmed by probes and all high-confidence/unflagged:**
  - "John & Jane Smith" → name "Smith Bakery" at 0.9 (`parser.py:220,236`). Detect multiple people, flag the card and cap confidence.
  - "P 330… / F 330…": the fax is typed as work, because `lab.split("/")[0]` keeps the text before the slash (`parser.py:87`).
  - "50 S Main St / 3rd Floor / Akron, OH" → only "Akron, OH" is kept, because a non-address line breaks the block (`parser.py:183-189`). Labels also leak in ("…Main St T").
  - "John Smith, CEO" loses the title, because `CRED` contains CEO (`parser.py:37`).
  - "Smith, John" comes out reversed; "van"/"de" names vanish (`parser.py:237`); compound surnames are cut to the last word (`parser.py:254`, `merge.py:73`).
  - The website TLD allowlist is too short (`.tech` → company) and disagrees with `ui.SITE_TLDS`. The email regex accepts `name@x.com.tel`. Use the public-suffix list.
  - QR vCard parsing doesn't unescape `\,`, join folded lines, or map ADR fields by name (`qr.py:43-46`). QR values get 0.99 confidence and skip the AI check, so these errors are never caught.

### CI / release
- **CI only tests Ubuntu with Python 3.12.** The product ships for Windows and macOS, and a Windows-only crash already reached a release (commit a1a7e98). Add a `{ubuntu, windows, macos}` matrix.
- **No accuracy gate.** Run `bench/eval_bench.py` on synth2 (~4 min) and fail if any field drops by more than one card. Give `tests/eval.py` an exit code and point it at `pipeline.scan`. Turn the probe cases above into fast parser unit tests.
- **No lint or audit steps.** Add `ruff check --select E9,F,B` (current real hits: `plausibility.py:40` duplicate dict key, `parser.py:129` late-bound loop variable, several unused variables) and pip-audit.
- **Release permissions and pinning.** `release.yml` gives `contents: write` to every job. Use top-level `contents: read` and grant write only to the `release` job. Also: `persist-credentials: false`; pin actions to commit SHAs; pin pyinstaller, pywebview, the choco/brew tesseract, and the WebView2 bootstrapper hash; add Dependabot.
- **Installers are unsigned.** `packaging/windows/sign.ps1` and `packaging/macos/sign_notarize.sh` exist but are never called. Wire them in with conditional steps, and add `actions/attest-build-provenance`.
- **Release version isn't checked.** Fail when the tag ≠ `VERSION`; take the release notes from CHANGELOG.
- **The lock file doesn't lock everything.** It pins 16 top-level packages but ~74 get installed. `rapidocr-onnxruntime` also pulls in full `opencv-python` next to the headless one. Use `pip-compile --generate-hashes`, and use the lock in Docker, `start.command` and `start.bat`, which currently install the open-ended `requirements.txt`. Pick one Python version: the lock says 3.13, everything else uses 3.12.
- **Docker images leave out files the app reads.** `VERSION` is missing, so the app reports 0.0.0 and the update banner always shows. `mctrade-dryrun/` is missing, so the MC Trade Excel falls back to built-in columns.
- **Windows upgrades keep stale files.** Add `[InstallDelete]` for `{app}\_internal` (`installer.iss`). Line 49 `taskkill /IM llama-server.exe` kills every llama-server on the machine, not just the app's.
- **AI helper can run out of memory.** It starts without `--cache-ram 0 -np 1`, and `start-ai-checker.command` notes that leaving them out caused OOM kills on 16 GB machines.
- **Desktop users have no restore path.** `scripts/restore_backup.sh` needs a source checkout.

### Security (Low)
- **vCard injection.** CR/LF in phone and social values isn't rejected or escaped (`export.py:40-45`), so a crafted value can inject extra contacts into the .vcf. Reject `[\r\n]` in all fields and escape every vCard value.
- **Public demo abuse:**
  - Visitors share one account, so uploaded photos are visible to everyone for up to 6 h.
  - `/api/phone/*` isn't blocked and returns the container's internal IP.
  - The card cap counts finished cards, not queued jobs, so parallel uploads get past it.
  - The Space downloads llama.cpp and the model without checksums (`Dockerfile.space`, `space/start.sh`); reuse the hashes in `ai_helper.py`.
- **llama-server has no `--api-key` or `--no-slots`.**
- **Login throttling is weak:**
  - It is per username only, so anyone on the LAN can lock out the admin.
  - There is no per-IP limit, and the failure counter grows without bound.
  - Unknown usernames skip PBKDF2, a timing oracle for which usernames exist.
- **Sessions:** expiry slides on every request with no absolute lifetime. `must_change` (forced password change) is enforced only in `ui.js:81`, not on the server.
- **Other:** a GET request performs a real export (`ui.py:~2346`); make it a POST. Desktop CSP allows `unsafe-eval`. The `key.pem` and DB file permissions follow the default umask.
- **Privacy wording:** the update check is on by default and calls api.github.com at startup, while README says "no cloud calls" and PRIVACY-NOTE says "nothing goes to the internet". Document it, or turn it off by default in server/Docker builds.

### Frontend / a11y
- **Session expiry during upload loses files.** A 401 mid-upload marks rows failed and they can't be recovered. Pause the queue, keep the rows, and add a Retry button.
- **Downloads bypass 401/403 handling.** `dl` and `tileExport` use raw `fetch`, skipping `call()`'s session and CSRF handling.
- **Approve is slow.** It makes 6-7 round-trips plus a forced 500 ms busy delay. Return the next pending id from the save response.
- **The "reload the page" link is blocked by CSP** (a `javascript:` URL, `ui.js:27`). Use a button with a handler.
- **Screen readers are flooded.** `#rAI` is a live region whose contents are replaced every 4 s, with a nested `role=status`. Announce state changes only.
- **Desktop app: the audit CSV link isn't routed** (`index.html:254`). Add a `download` attribute.
- **Phone:**
  - The service worker is cache-first with a fixed cache name, so it serves old `phone.js` forever. Version the cache or remove the SW.
  - The camera stream is never stopped when the tab is hidden.
- **Toast:** the Undo button stays focusable after fading, and the 4.5 s timeout is too short for keyboard users (WCAG 2.2.1).
- **Tabs:** `role=tab` is used without tabpanels or arrow-key handling.
