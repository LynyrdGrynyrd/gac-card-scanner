# CLAUDE.md: working on the GAC Card Scanner

Local, CPU-only FastAPI + SQLite app: business-card photo → QR/OCR → rules parser → human review (`/ui`) → CSV / vCard /
MC Trade Excel. One process, one SQLite file, thread pools. Ships as Windows/macOS desktop apps (pywebview) and Docker.

Read first, as needed: `HANDOFF.md` (architecture, data model, env vars, server-enforced rules), `docs/AUDIT-2026-10-15.md`
(the audit and what is still open), `CHANGELOG.md`, `OSS-SURVEY.md` (**libraries already evaluated, with measured results:
check it before proposing a new OCR engine, parser library or matcher**), `tests/unit/README.md` (feature → test file).

## Commands
```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.lock.txt -r requirements-dev.txt   # + system tesseract-ocr
.venv/bin/python -m pytest -q tests/unit            # ~2-5 min; all data goes to a temp folder (tests/unit/conftest.py)
.venv/bin/python -m pytest -q tests/api             # Schemathesis fuzzing of the HTTP API (in-process)
.venv/bin/python -m pytest -q tests/e2e             # Playwright browser flows (needs Chromium)
.venv/bin/python tests/eval.py --min 108            # accuracy gate: 108/108 fields on tests/cards
.venv/bin/python bench/eval_bench.py tests/synth2_gt.json tests/synth2 --min-overall 96   # accuracy gate: full pipeline
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8765 --reload                    # run it; first visit creates the admin
```
Lint exactly as CI does (`.github/workflows/ci.yml`, job `lint`):
`ruff check --isolated --select E9,F63,F7,F82,B006,B008 --config "lint.flake8-bugbear.extend-immutable-calls=['fastapi.Body','fastapi.File','fastapi.Form']" --config "lint.per-file-ignores={'app/vlm.py'=['B008']}" app tests`

CI runs the unit tests on **Ubuntu, Windows and macOS**, plus ruff, pip-audit, the accuracy gates, API fuzzing and e2e.
In Claude Code cloud sessions `.claude/hooks/session-start.sh` installs Tesseract and a `.venv` automatically.

## Hard rules
- **No real personal data in the repo, ever.** Test/demo cards are generated (fictional people, 555 numbers). Real card
  photos, the pilot database, exports and benchmark copies stay in git-ignored folders (`data/`, `bench/real/`,
  `bench/corrections/`, `qa/**` media). Check `git status` before committing anything under `bench/` or `qa/`.
- **Writes:** a request that writes more than one row runs inside `with WRITE_LOCK, store.tx():` (`app/ui.py`,
  `app/store.py`): one transaction, rolled back if anything raises. Card saves compare the card version under the lock
  (optimistic locking). `ui.set_meta` updates only the columns passed; never write back a whole row you read earlier
  (`INSERT OR REPLACE` of a stale row undoes other writers). Schema set-up goes through `store.once`, connections through
  `store.connect()` / `db()` (WAL, busy timeout).
- **Background threads** (AI worker, phone reaper, retention) catch and log per iteration; one failure must not kill the loop.
- **Module layout:** `app/ui.py` re-exports names from `pages`, `privacy`, `exporting`, `audit_log`, `admin_files`. Those
  modules do `from . import ui as U` and call `U.<name>` at call time, so tests that monkeypatch `ui.<name>` still take
  effect and there are no import cycles. Follow the same pattern; don't import ui names directly into those modules.
- **Importing `app.main` has no side effects** (no AI helper start, no demo wipe); start-up work belongs to serving.
  `tests/unit/test_audit_p2.py` checks this.
- **Server enforces, UI mirrors:** reviewer identity comes from the session (never from the request body); approve needs
  `validate()` or an override reason; exports re-check versions. Don't move a rule into the frontend only.
- **Frontend:** plain ES modules under `app/static/ui/{core,ui,views}`, no framework, no build step. Shared mutable page
  state lives in `core/state.js` (`S`). CSP is `script-src 'self'`: no inline scripts or `on*=` attributes. Every value put
  into `innerHTML` goes through `esc()`. Bump nothing by hand: `auth.asset_version` hashes the UI JS for cache-busting.
- **Dependencies:** change ranges in `requirements.txt`, then regenerate `requirements.lock.txt` with the `uv pip compile`
  command in its header. Never hand-edit the lock. Test tools are pinned in `requirements-dev.txt`.
- **Cross-platform:** close files you open (openpyxl workbooks: `wb.close()`; Windows locks open files), no POSIX-only
  calls without a fallback, no hard-coded `/` paths, no reliance on file modes in tests.
- **Privacy features are product behaviour:** photo retention, delete-on-request (tombstones, hard delete) and the audit
  log must keep working for anything new that stores card data (copies included).

## Accuracy work
- Measure before and after on both gates. Synthetic gains are weak evidence (the sets are generated by the same team);
  the pilot's real-card set is not in the repo. Build one from a scanner's database with
  `bench/extract_eval_set.py --data-dir <data folder>` (read-only; writes to the app's corrections folder, covered by
  retention) and score it with `bench/eval_bench.py <out>/gt.json <out> --show`.
- `OSS-SURVEY.md` lists what was tried and rejected (PP-OCRv5, docTR, usaddress, probablepeople, rembg, Splink, GLiNER)
  with numbers. Its 2026-10-15 re-check led to RapidOCR 3.x + PP-OCRv6 small (adopted: `app/ocr.py` passes the bundled
  model paths so it never downloads; only `opencv-python-headless` is installed). Not yet confirmed on real cards: do
  that before the next release (see CHANGELOG).
- `tests/synth2` is a development set: the same generator with other seeds scores ~20 fields lower. Check a parser
  change on freshly generated cards too, not only on synth2.

## Tests and style
- Every fix gets a test. Unit tests use the session-scoped `env` fixture (shared DB): give your cards a unique batch
  label so other tests' cards don't leak into your assertions. `mk()` in `tests/unit/test_app.py` makes a card.
- Test files are named after review rounds (`test_r*.py`) and audit parts; they are deliberately not renamed.
- Match the surrounding code: compact lines, short names, comments that say **why** (often tagged `audit 2026-10` or a
  round number), not what. Minimal diffs; don't reformat code you aren't changing.
- Git: feature branches, PRs merged with merge commits (not squash). Update `CHANGELOG.md` (user-facing wording) with
  behaviour changes.

## Open product decisions (ask the owner, don't decide in code)

date; code-signing certificates. See the "Still open" list in `docs/AUDIT-2026-10-15.md`.
